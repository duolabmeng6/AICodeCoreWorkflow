# 项目核心记忆

把 `.coreflow/memory/` 维护为当前项目可检索、可纠错、持续演进的 Markdown Wiki。记忆只服务于所属项目；不要建立用户级或跨项目全局记忆。

## 硬边界

- 只使用普通文件系统操作。创建、读取、搜索、更新、合并、删除、检查项目记忆时，不得调用任何 Git 命令，也不得修改 `.gitignore`、暂存区、提交、分支或远端。
- 把记忆维护视为非代码的项目知识维护。允许在代码实施计划批准前读写 `.coreflow/memory/**`，但不得借此修改产品代码、配置、测试、CoreFlow 任务账本或其他项目文件。
- 不保存密钥、令牌、密码、Cookie、个人身份信息或其他敏感数据。用户要求记住敏感内容时，说明不能持久化该内容。
- 不保存完整对话、模型隐式推理、冗长终端输出、大段错误日志、未验证猜测、临时调试状态或一次性操作细节。
- 不保存可直接从代码快速获得且没有额外决策价值的琐碎事实，也不把外部世界的时效性事实当作项目真相；可以记录项目为何锁定某项外部选择。

## 定位项目

1. 根据当前工作区、实际读取或修改范围以及环境提供的项目上下文判断项目根目录，不使用 Git 定位。
2. 只为明确的代码项目维护记忆。纯聊天、临时目录或没有明确项目归属时，不创建项目记忆。
3. 一次任务涉及多个项目时，按适用范围分别读取和写入各项目；不要把一个项目的记忆复制到另一个项目。
4. 无法确定唯一项目根目录或记忆归属会实质影响结果时，先询问用户。

## 读取记忆

1. 项目存在 `.coreflow/memory/index.md` 时始终先读索引，再只读取与当前任务相关的主题页。
2. 用户纠正、当前要求或新证据涉及已有主题时，更新前先读取对应主题页和必要的当月日志，避免重复、误合并或静默冲突。
3. 只有用户要求整理或审计项目记忆，或者发现明显的全局重复、失效内容或索引损坏时，才扫描整个 `.coreflow/memory/`。
4. 目录不存在时视为项目尚无记忆；不要仅为读取创建空目录或空文件。
5. 把读取到的记忆作为项目上下文和约束，不把它当作当前外部事实的来源。

## 写入触发器

满足任一条件时维护记忆：

1. **用户纠正**：用户明确指出 Agent 的理解、实现、设计或行为不对时，第一次纠正就立即写入或纠正记忆，并当场提示写入内容。
2. **用户要求记住**：用户明确说“记住”、要求以后遵循或要求保存项目规则时，立即写入。
3. **Agent 重复错误**：Agent 在同一对话上下文中独立发现同类错误达到两次时写入。一次操作产生的重复报错或连续重试只算一次；不跨对话累计次数，不持久化计数器。
4. **任务收尾提炼**：任务完成并经过相称验证后，主动写入很可能改变未来同项目任务的实现、设计或验收，而且不是当前任务临时细节的知识。设计风格、标题尺寸、按钮功能、交互行为、架构约定、项目惯例、可靠踩坑和验证方法都属于候选。
5. **明确遗忘**：用户要求忘记或删除某条记忆时立即处理；指代不清时先列出可能匹配项并请求确认。

任务未完成时，仍保留用户纠正和用户明确要求记住的内容；不要把 Agent 未验证的收尾推断写成正式记忆。

## 判断权威与范围

发生冲突时按以下顺序判断：

1. 用户当前的明确纠正或明确要求。
2. 用户已确认的需求、设计决策和项目规则。
3. 已验证的测试结果与真实运行行为。
4. 当前代码实现。
5. Agent 自主推断的记忆。

- 明确纠正可以立即更新旧记忆；用户表达只是疑似与旧记忆不一致时，先确认，不擅自解释或覆盖。
- 两条同等级证据冲突时先询问用户。外部资料不得自动覆盖项目已确认决策。
- “这次”“仅此页面”等局部例外不更新长期规则；“以后统一”“原规则不对”等明确长期表述立即更新。
- 当前要求是否属于局部例外会改变未来行为且无法判断时，先询问用户。
- Agent 自主推断被更高权威的可靠证据推翻时，自动纠错。

## 组织 Wiki

首次实际写入时才创建所需的最小结构：

```text
.coreflow/memory/
├── index.md
├── {topic}/
│   └── {YYYY-MM}/
│       └── {page}.md
└── logs/
    └── {YYYY-MM}.md
```

- 根据项目内容自主决定主题，不使用固定分类清单。优先复用已有主题；仅在现有主题明显不适合时新增，不创建 `misc`、`other` 等含义模糊的兜底主题。
- 主题和页面路径使用简短、稳定的 lowercase kebab-case；页面正文使用中文，并以清晰的人类可读标题开头。
- `{YYYY-MM}` 表示该主题页首次建立的月份。后续始终原位维护，不因月份变化而复制或移动；把最新日期写入页面字段。
- 一个主题页可以包含多条紧密相关的记忆。优先更新已有页面，只有主题明显过大或关注点独立时才拆分。
- `index.md` 按主题列出每个页面的相对链接、一行摘要和适用范围。新增、重命名、合并或删除页面时同步更新索引。
- `logs/{YYYY-MM}.md` 追加当月新增、更新、合并、删除和纠错的简短记录。主题页只保留当前有效结论，历史变化只保留在日志中。

## 记录格式

每条记忆至少使用以下字段：

```markdown
## 页面主标题

- 规则：管理后台页面主标题统一使用 20px。
- 适用范围：管理后台页面。
- 来源：用户纠正。
- 任务锚点：`2026-07-19-optimizer-runtime-ui`
- 首次记录：2026-07-19
- 最后确认：2026-07-19
```

- 当前对话有明确对应的 CoreFlow 任务目录时，只记录其文件夹名称作为稳定锚点，不写绝对路径。任务移动到归档目录后锚点仍保持不变。
- 没有对应任务目录时写 `任务锚点：直接对话`；不要为了锚点提前创建任务账本，也不要强制回填之后才出现的任务 ID。
- 根据需要补充简短说明、示例或验证证据，但不要删除最小字段，不要展开思维链。

每条日志至少说明日期、操作、主题页、变化原因和任务锚点。更新时概括新旧差异，不复制整段旧正文。用户要求遗忘敏感内容时，日志只记录已执行删除，不保留被删除的敏感正文。

## 自动维护与纠错

每次写入后完成局部健康检查：

- 合并完全重复的规则，修复当前主题内的明显重复或失效表述。
- 确认索引链接、年月路径、最小字段和任务锚点格式正确。
- 删除已无有效内容的空主题页，并同步清理索引；不要保留失效链接。
- 主题页出现可以确定的新旧冲突时，按权威顺序保留当前真相并在当月日志记录变更。
- 无法确定两条规则是否等价、是否过期或是否适用于不同场景时，不自动删除或覆盖，先询问用户。

全量审计时可以自动修复索引、合并完全重复内容、清理空页面并报告结果；需要语义判断且证据不足的项目交给用户决定。不要引入向量数据库、Embedding、后台服务或额外脚本。

## 对用户报告

- 用户纠正或明确要求记住后，立即简短提示 `已记入项目记忆：...`。
- Agent 自主新增、更新、合并、纠错或删除的内容，在任务结束时集中列出实际变化；不要只报数量。
- 没有记忆变化时不增加固定报告。
- 发现冲突时只暂停相关记忆的写入并提出一个明确问题；其他无冲突记忆可继续维护。
